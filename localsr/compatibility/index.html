Workarounds

Linux AMD: join video and render groups

For: Everyone running the Linux ROCm engine on an AMD GPU. Log out and back in after running this.

Terminal
sudo usermod -a -G video,render $USER

Undo: Run sudo gpasswd -d $USER render and sudo gpasswd -d $USER video, then log out and back in.

Risk: Grants your user account direct access to local GPU and video device nodes.

Linux AMD RX 6600-6800 (RDNA2): 10.3.0 override

For: Linux AMD RX 6600, 6700 and 6800 series GPUs (gfx1031, gfx1032, gfx1034).

Terminal
HSA_OVERRIDE_GFX_VERSION=10.3.0 ./LocalSR-...-Linux-ROCm-x86_64.AppImage

Undo: It is only an environment variable for that launch. Close LocalSR and unset HSA_OVERRIDE_GFX_VERSION, or start the AppImage without it.

Risk: At your own risk: common workaround, not confirmed on ROCm 7.2. LocalSR's GPU check compares each model with the CPU before using the GPU; if results are wrong or the GPU hangs, unset it and use the CPU.

Linux AMD integrated graphics: APU memory and kernel flags

For: Radeon 680M/610M (gfx1035, gfx1036) and Radeon 780M/760M (gfx1103) integrated GPUs, as a last resort when runs fail or hang.

Terminal
pipx install amd-debug-tools
amd-ttm --set <GB>

Reboot after amd-ttm --set <GB>. Only as a last resort on gfx1103, add kernel parameter amdgpu.cwsr_enable=0.

Undo: Run amd-ttm --clear and reboot. Remove amdgpu.cwsr_enable=0 from your bootloader config and reboot.

Risk: At your own risk: display shares the GPU so runs can hang the desktop, and AMD does not test amdgpu.cwsr_enable=0.

Linux Intel Gen9-11: legacy1 compute-runtime

For: Linux Intel Gen9 to Gen11 integrated graphics (Skylake to Ice Lake). After installing intel-opencl-icd-legacy1 and intel-level-zero-gpu-legacy1 from intel/compute-runtime releases, the GPU shows as (OpenVINO).

Terminal
sudo apt install ./intel-opencl-icd-legacy1_*.deb ./intel-level-zero-gpu-legacy1_*.deb

Undo: Remove both packages with your package manager (for example sudo apt remove intel-opencl-icd-legacy1 intel-level-zero-gpu-legacy1).

Risk: Replaces or pins the system OpenCL and Level Zero packages with the legacy1 release.

Windows GTX 9xx, GTX 10xx and Titan V: DirectML engine

For: Windows systems with NVIDIA Pascal, Maxwell or Volta cards (dropped by CUDA 13). Use the DirectML edition instead of CUDA, or switch engine in the app from the next release.

App setting
Advanced settings > Hardware > Engine -> DirectML

Undo: Switch Engine back to CPU, or uninstall the DirectML edition.

Risk: LocalSR checks each model against the CPU first and falls back to CPU if DirectML results differ.

Not worth trying (use CPU instead): Intel HD 4000 and older, AMD RX 5000 (RDNA1), AMD Vega 56 / 64 / Radeon VII / Vega APUs, and any ROCm override on Windows.

Let your coding agent do it

On Linux with an AMD GPU, you can paste this self-contained prompt into your coding agent to diagnose your card and set up a safe launcher script when applicable.

Prompt for your coding agent

Copy the full prompt below, or open agent-prompt.txt directly.

agent-prompt.txt
Goal: Check an AMD GPU on Linux for LocalSR's ROCm engine. If there is no AMD GPU: for NVIDIA, recommend the CUDA engine for Turing or newer with driver 580+; older NVIDIA uses CPU on Linux. For Intel, recommend the OpenVINO route (see the LocalSR compatibility page). Stop without changes and report.

Run these read-only diagnosis commands first (do not change anything yet):
1. lspci -nn | grep -iE 'vga|3d|display'
2. If rocminfo is installed: rocminfo | grep -i gfx
3. groups
4. uname -r
5. Find the LocalSR AppImage path (check common locations such as ~/Downloads, ~/Applications, or ~/.local/bin, or ask me if it is not found).

Match the detected GPU / gfx ID against this lookup table:
- gfx1030, gfx1100, gfx1101, gfx1102, gfx1200, gfx1201 (RX 7000/9000, Radeon PRO W7000, W6800): Supported natively on ROCm. No HSA_OVERRIDE_GFX_VERSION override is needed. Check that amdgpu is in use and the user is in the video and render groups.
- gfx1150, gfx1151: Supported natively on ROCm, no override needed, but requires Linux kernel 6.17.0-19 (Ubuntu HWE) or 6.18.4 or newer, plus amdgpu and video + render groups.
- gfx1031, gfx1032, gfx1034 (RX 6600-6800, RDNA2): Works with workaround (common, not confirmed on ROCm 7.2). Run the ROCm AppImage with HSA_OVERRIDE_GFX_VERSION=10.3.0. Note: at the user's own risk; LocalSR's GPU check compares each model against the CPU before using the GPU.
- gfx1035, gfx1036 (Radeon 680M / 610M iGPU): Experimental. Uses HSA_OVERRIDE_GFX_VERSION=10.3.0, with hang risk because the display shares the GPU, and may need APU memory settings (amd-debug-tools / amd-ttm). Do not change system settings or install tools without asking first and explaining the hang risk.
- gfx1103 (Radeon 780M / 760M iGPU): Experimental (native target in torch 2.13, no override needed). GPU hangs and MES errors have been reported; kernel flags such as amdgpu.cwsr_enable=0 are a last resort only (AMD does not test them). Do not edit bootloader or kernel flags unless explicitly asked after reading the risk.
- gfx900, gfx902, gfx906, gfx90c (Vega 56/64, Radeon VII, Vega APUs), gfx1010, gfx1012 (RX 5000, RDNA1), or any other unlisted AMD GPU: CPU only. Do not apply overrides; report that LocalSR should run on CPU.

Hard rules:
- If the user is missing video or render group membership, show exactly `sudo usermod -a -G video,render $USER` and say to log out and back in. Never run this command. You may still create the permitted launcher.
- Never run sudo or change system settings without asking me first and showing the exact command (including installing packages or setting amd-ttm).
- Never install packages from outside the Linux distribution repositories or official AMD/Intel sources.
- Never edit bootloader or kernel flags unless I explicitly ask you to after reading the risk.
- Never disable security features.
- Never download a different LocalSR build.
- Stop immediately and report if you see any GPU hang, kernel error, or MES error.

Only change allowed without asking first:
- If the GPU is a documented override case (gfx1031, gfx1032, gfx1034) and you found the LocalSR ROCm AppImage, you may create a small launcher script in my home directory (for example ~/.local/bin/localsr-amd) that exports HSA_OVERRIDE_GFX_VERSION=10.3.0 and execs that AppImage, make it executable, and print the exact command to delete it.

Finish with this exact report format:
Detected GPU + gfx ID: <value>
Matched rule: <row from the table above>
What was changed: <file/action or "nothing">
How to undo: <exact command or "nothing to undo">
Next step: <e.g. "Start LocalSR with ~/.local/bin/localsr-amd and check Advanced settings > Hardware" or "Use the CPU build/engine">

Last checked: 22 November 2026. Actual behaviour and stability depend on your graphics driver version.
