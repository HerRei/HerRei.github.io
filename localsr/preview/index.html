These changes are being prepared on the isolated codex/hdr-preservation branch, with Linux and Windows fixes on codex/platform-acceptance, for a later release. They do not announce a new downloadable installer or change the ongoing v0.0.12-alpha release. Existing download links still refer to their published release.

Choose what happens to HDR

Supported camera MOV files keep their portrait orientation and original timing. For BT.2020 HLG or PQ input, the preview offers two explicit output choices:

The models were trained on SDR. Stock HAT and the two face forks have no established HDR perceptual-quality result. The preservation adapter retains each source pixel’s mean linear RGB across its expanded block; its detail can show block boundaries or temporal artefacts. It remains an experiment, with higher memory use than SDR.

All in-app thumbnails and live render tiles are labelled SDR display previews. They do not demonstrate HDR playback. Compatible Dolby Vision files use their HLG/PQ base layer; dynamic Dolby Vision metadata is omitted. Other colour primaries/matrices, SeedVR2 HDR preservation, and HDR de-flicker are unsupported. No new mastering-display or content-light metadata is invented.

Selecting SeedVR2 switches colour output to SDR and disables HDR preservation. Custom checkpoints retain the option; the worker checks compatibility with the HAT preservation adapter when loading.

Watch actual model tiles

The centre shows an animated welcome state and real loading phases for large images and videos. During upscaling, the active square follows the model’s current tile; finished squares contain sampled model output. The current decoded video frame stays visible beneath a translucent HAT grid and updates as processing advances. Frame ownership prevents an older source preview or completed tile from being painted into a newer frame. Pending squares and the active outline now share the exact canvas boundaries of the completed tiles, including partial edge tiles.

ETA begins after the first completed tile, including within the first video frame. Until then, the app says it is measuring. Estimates update from observed work and can change with scene complexity and encoding time.

Choose an output your hardware can handle

SeedVR2 has a separate output-resolution choice. Keep the selected scale, or choose a smaller edge from 256 to 2160 pixels. Choosing a smaller size can downsample a large source; the app shows the resulting dimensions and warns about the loss of fine detail before Start.

The FP16 and FP8 variants support AMD ROCm as well as NVIDIA CUDA. FP8 reduces weight storage; it does not guarantee that a video fits in 16 GB. Reduce GPU memory uses shorter clips and smaller VAE tiles. On CUDA and ROCm it also moves diffusion blocks and working tensors to system RAM, trading transfer time and RAM for lower GPU residency. Live diagnostics show the current stage, allocated and reserved GPU memory, free VRAM where available, and worker RAM. Memory errors retain those measurements and suggest a smaller output or tiled HAT-S.

The preview buffers one model window and moves inactive model weights off the GPU between stages. Its activity indicator follows real loading, encoding, enhancement and decoding work; ETA begins after the first completed clip. Outlines follow the actual overlapping VAE regions, while diffusion highlights the whole frame because it processes the clip together. Enhanced pixels appear after the model finishes the clip. GPU memory limits stay enabled.

On a Radeon RX 9060 XT with 16 GB, the installed FP8 worker completed five frames from a rotated 4K HLG source at 2160 × 3840 SDR in 277.6 seconds, with 9.93 GiB peak PyTorch allocation. A longer check completed 20 frames at 720 × 1280 SDR across multiple model windows, with ordered timing and inspected colour output. Cancellation during diffusion also allowed a subsequent job to complete. Small VAE tiles still show visible grid seams.

On a 16 GB Apple-silicon Mac, the real model completed ten frames from a rotated 4K HLG source at 256 × 454 SDR, through three clips, in about 4½ minutes. Timing and stereo AAC were retained. These short checks do not establish long-clip quality, faithful restoration, or practical full-length 4K/8K processing.

SeedVR2 remains experimental and exports SDR. A model being installed does not mean every output resolution fits the available memory. The frame-by-frame engine is available when its memory use or processing time is too high.

CPU or GPU. Separate scores.

Choose CPU or a detected GPU before starting. On Apple silicon, the GPU option uses MPS/Metal. A run measures that selection only. Each device’s latest completed result is saved separately, including its timing spread and date; a CPU run preserves the previous GPU result.

The fixed v2 workload still uses SPAN at 4× across compute, tiled processing, and image-export scenes. Each score is the geometric mean of output megapixels per second. There is no combined CPU/GPU score, and results above 5% timing spread remain visibly unstable.

The benchmark viewer shows real render squares using the same tile geometry as the HAT viewer. Pixels come from the unmeasured warm-up; scored iterations run without preview encoding. This is a speed measurement, not a model-quality comparison.

Checked locally, with limits

The comparison player can reopen previously viewed results after switching between queued videos. Linux testing found that WebKitGTK could reject valid videos through the app’s custom file transport. The preview now streams authorized files locally with normal byte-range seeking. Actual Linux playback passed, including returning to a completed video while another job runs. Loading feedback and a retry control distinguish a player failure from a damaged export; the speed selector starts visibly at 1×.

Installed CPU and AMD workers passed real image and video checks covering transparency, Unicode filenames, trims, audio, actual tiles, ETA, cancellation and retry. Linux GUI tests also completed separate CPU and AMD benchmarks. The diagnostics panel now identifies the processor selected for that benchmark, rather than showing the device used for ordinary jobs.

A disposable Windows VM passed native tests and real inference through the frozen CPU worker, including video export, audio and recovery after cancellation. Follow-up fixes improve first-tile timing on Windows; their final Windows rerun remains outstanding. Windows GPU drivers and signed installation still need acceptance.

Automated checks cover floating-point inference and face blending, more than 700 distinct encoded luma levels in a 10-bit gradient, HLG/PQ transfer functions, colour tags, variable frame timing, audio, and separate device selection.

On Apple silicon, both exact face checkpoints also completed bounded real HLG and PQ inference. A short rotated 4K HLG MOV export retained its HDR tags and stereo AAC. This is functional acceptance on short samples, not a completed multi-minute 4K upscale, HDR quality certification, or all-platform installer acceptance.
