LocalSR v0.6.0-beta

The largest LocalSR release so far: its own photo models, FlashVSR, de-flicker and colour for video, one Settings window and a first launch that starts with privacy.

In v0.6.1-beta

A hotfix for 0.6.0: the Mac engine starts again on macOS 14 and 15, videos no longer freeze the Linux AppImage, and a few smaller fixes. Update from inside the app, or download it again.

  • The Mac engine starts again on macOS 14 and 15. 0.6.0 contained a part of MLX (the library behind FlashVSR) that only macOS 26 can load, so on older macOS the engine stopped right at start with “The inference engine ended unexpectedly” (#183). 0.6.1 ships the macOS 14 build of MLX, and a release check now refuses any file that needs a newer macOS than LocalSR supports. If MLX ever fails to start, only FlashVSR is turned off; the rest of LocalSR keeps working.
  • Videos with repeated timestamps. Some videos have frames with the same or an earlier timestamp than the frame before (cuts without re-encoding, screen recordings, some phone videos). LocalSR stopped with “Video presentation timestamps must increase”; it now processes them (#177).
  • Stuck on the CPU after the GPU went missing once. When the engine started once without the GPU (for example while the disk was full), LocalSR saved the CPU as the device and kept every later run on the CPU, even after the GPU was back. It now keeps your device and only runs on the CPU while the GPU is missing. Work that runs on the CPU now always uses full precision there: half precision on the CPU took many minutes for a single tile. If LocalSR has run on the CPU since 0.6.0 although your computer has a GPU, choose the GPU again under Settings.
  • Linux: videos froze the app (#185). The AppImage contained GStreamer, which plays video in the app window, but none of its plugins. On distributions that keep their plugins elsewhere (Arch, CachyOS, Fedora) or ship a newer GStreamer, adding a video froze LocalSR. The AppImage now brings its own royalty-free plugins and uses only those, and every Linux build plays a test video with them before it is released.
  • Editing on AMD laptops with Vulkan (#131). Edits stopped with “The Vulkan runtime cannot uniquely identify the selected GPU” when PyTorch and the graphics driver named the same GPU differently, for example “AMD Radeon Graphics” and “AMD Radeon 780M”. LocalSR now uses the only GPU of the same make in that case, and follows GGML_VK_VISIBLE_DEVICES as the message advises. It still refuses a different card.

In v0.6.0-beta

The largest LocalSR release so far. Quick for photos now runs on LocalSR's own model, trained only on public-domain photos. Video gets FlashVSR, a new de-flicker engine and colour. Upscaling and restoring are one task, every app-wide choice sits in one Settings window, and a new install starts with a privacy page that says what is sent and why.

LocalSR's own models

Two x4 photo upscalers by Hermes Reisner, LocalSR Photo S and LocalSR Photo M (4xLocalSRPhoto_PULSE-64x8 and 4xLocalSRPhoto_PULSE-96x12, weights CC BY 4.0). Both are trained only on public-domain (CC0) photos and run fully on the Neural Engine.

  • Photo S is the new Quick for photos. On a sealed test set of 99 photos it beats the SPAN model it replaces on every measure, at the same speed.
  • Photo M is the fast alternative to Best. It shows no clear difference in detail from NomosWebPhoto, keeps 2.6 dB more fidelity and runs about four times as fast (27 s instead of 99 s for a 12 MP photo on an M1 Pro). Best stays NomosWebPhoto; Photo M is in the model library.
  • The models, their numbers and the technical report are at github.com/HerRei/localsr-models.

Photos

  • Upscale & restore. Restore is no longer a separate task. The Size row (Same size, 2×, 3×, 4×) decides whether the picture gets bigger, and the Fix chips (Noise, Blur, JPEG artifacts, Colour) work at any size. Quick and Best choose the fix models too: a fast one or the most careful one. Saved recipes and settings keep working.
  • Illustration Best. Best for illustrations now uses ESRGAN ×4 HFA2k, which keeps flat colours, white backgrounds, QR codes and fine lines. RealPLKSR HFA2k stays in the model library (#122).
  • Your own models. Own checkpoints get a name you can change and their own group in the model picker. A .pth, .pt or .ckpt file is confirmed once per file, not per job. NERVE and HEART checkpoints load too (#146, #154).

Video

  • FlashVSR v1.1 · Labs. A one-step diffusion video upscaler for Apple silicon Macs with 16 GB or more (MLX), AMD ROCm on Linux and NVIDIA CUDA on Linux and Windows with 12 GB or more VRAM. It works on 37 frames at a time with 8 frames of run-up, splits large frames into tiles sized to the available memory and follows the output size you choose (up to 4× directly, larger sizes are resized). The weights (6.4 GB, Apache-2.0) download on first use. CUDA has not been run on NVIDIA hardware yet.
  • De-flicker. A new engine for every frame-by-frame model. It evens out brightness flicker in the original and the shimmer that upscaling adds in still areas, decided from the original, so motion, cuts and real light changes pass through. It removes more shimmer than before at about 40 ms per frame. Still off by default.
  • Colour for video. Black-and-white videos can be coloured with the Colour fix, at any size. Colours are carried from frame to frame, so they stay steady. A video that already has colour skips the step (#164).
  • Video models in the model list. SeedVR2 and FlashVSR are chosen like any other model, with quality and speed ratings. A "?" explains frame by frame against several frames at once, and models that cannot run on this computer say why.
  • Heavy video jobs. Frame interpolation after upscaling needs about half the graphics memory. When a frame pair still does not fit, the other models wait in system memory, so very large videos stay on the GPU; only as a last resort does it run on the CPU, and the result says so. Running out of graphics memory reads as a plain sentence with what to change.

Stopping, comparing, progress

  • Stopping a job. Cancel asks whether to keep the finished part or discard it, and Settings can make that choice permanent. A video keeps its finished frames, a photo its finished tiles with the rest left as in the original, also in a queue. Kept parts are marked Unfinished and appear in Outputs; a photo shows its finished tiles on hover.
  • Compare. Choose which side's audio plays and step frame by frame. Each side lists how it was made: models and fixes in order, scale, size, time, device and date (#145). An unfinished video is compared over its kept frames only.
  • Progress. The status line names the step that runs (for example Adding colour or De-flickering, with a count), downloads share one progress bar, and Saving the result appears only while the file is written. Interpolation can be moved before or after upscaling from the plan list.

The app

  • First launch. A two-page setup. First privacy: update checks, the anonymous count and crash reports, each with a plain explanation and a link to what LocalSR sends and why. Then the look of the app, the menu bar or tray icon and a sound when a file finishes. Nothing is sent before Done.
  • Settings. One Settings window (⌘, on a Mac; File > Settings… elsewhere) holds every app-wide choice: appearance, default hardware, low priority, notifications and sound, the menu bar icon, the model folder, caches, External FFmpeg, updates and crash reports. Advanced chooses the hardware and low priority for this session only. After a GPU failure, Retry on CPU runs that job on the CPU without changing the default.
  • High contrast. Stronger text, borders and focus outlines in the dark and the light theme. It also turns on when the computer asks for more contrast.
  • Viewer background. Checkerboard, black, neutral grey or white, in Settings or from the swatch beside the zoom controls. Preview, Compare and video use it.
  • Menu bar. An icon in the menu bar or system tray shows what is running, how many files wait and the progress, with Pause and Resume and a notification for each finished file. On a Mac it can be monochrome or in colour (#112).
  • Cache. Settings show the size of the compiled model caches with Clear cache, which asks first; unused entries are removed automatically unless you turn that off (#126).

Install and updates

  • Updates from 0.4.0 and 0.5.0. They refused the update to 0.5.2 ("unknown field arch"). The update files are again in a form they read, an engine they installed is taken over, and every release is now checked against the updaters of older releases before it ships.
  • Debian package. The CPU edition for Ubuntu 22.04+ and Debian 12+ as a .deb that apt installs into the applications menu and removes with apt remove. It reports new versions instead of updating itself and downloads the CUDA or ROCm engine inside the app. The AppImage stays (#165).
  • Windows installer. Offers Just me (default, no administrator rights) or Everyone on this computer.
  • GPU engines. Program files are checked at every start, a reinstall keeps the working copy until the new one has started, and linked engine folders are refused (#159).
  • Settings from a newer version. LocalSR keeps the file untouched, runs with defaults and says so, and an update to that newer version is no longer blocked (#123).

Fixes

  • Comparing videos no longer stutters, stops where an unfinished part ends and keeps its position and audio choice when you switch between Slider and Boxes.
  • The live preview of Colour plus upscaling stays in colour.
  • Stopping a large photo with "keep the finished part" gives it the time to save instead of restarting the engine after a few seconds.
  • LocalSR's own OpenCV now includes optical flow, which de-flicker and video colour need.
  • The video encoder is always flushed before it closes (#115). Release files can be attached to a draft release, and signing needs less disk space (#114).

Known limitation

While a comparison of two videos plays in the Mac app, the two sides can be a few frames apart; paused and stepped frames always match. A frame-exact fix is planned for 0.6.1 (#176).

In v0.5.2-beta

What changed

  • Engine manager. One main download per OS starts LocalSR. After setup, the app can recommend and download a GPU engine. Change, remove or import an engine from a file in Advanced settings; the bundled engine remains available (#148, #150, #157).
  • Colour. Colour black-and-white photos with DDColor before upscaling, or with Restore (#153).
  • Your own edit models. Choose GGUF files for a supported edit model family. LocalSR checks the model before saving it and leaves your files in place (#152).
  • Model folder. Choose where downloaded models live and move them safely. If the folder is missing, choose it again or return to the default (#151).
  • Stopped videos. Keep the finished part as a playable video, with audio and subtitles cut to match. FFV1-master conversions still discard unfinished files (#147).
  • RTX 50 and CUDA 13. CUDA now supports RTX 50 cards and needs NVIDIA driver 580 or newer. GTX 10 and older use DirectML on Windows or CPU on Linux (#149).
  • Windows graphics. LocalSR recommends a GPU engine for supported graphics cards; new DirectML installs select the best available adapter (#150).
  • Downloads and installers. The download table shows the main file for each OS. Offline GPU packages remain available, and the CUDA installer names missing or invalid engine parts (#155, #156, #157).
  • Unsupported models. A checkpoint that cannot be loaded now shows its likely architecture and links to the issue for newer architectures (#154).
  • Restore first. Fix first is now called Restore first and uses the same problems, in the same order, as Restore. Upscale starts at 2x; to keep the size, use Restore. Settings saved at 1x open as Restore. Video Restore with nothing picked runs only De-flicker, Frame rate and Clean up audio.
  • Faces removed. The Faces option is gone from the problem list; saved settings drop it.
  • Mage-Flow edit model. A fast edit model (MIT licence, 4 steps). On Macs it runs on the CPU, about 1.5 minutes at 512 px; on NVIDIA and AMD graphics it uses the GPU.
  • Windows installer. Installs for your account without administrator rights. You can choose the folder, get a Start menu entry and an optional desktop shortcut, and start LocalSR from the last page. Uninstalling keeps your downloaded models and settings unless you tick the box to remove them.
  • Linux menu entry. After the first-launch setup, the AppImage offers once to add LocalSR to your applications menu. The Help menu removes it again.
  • GPU engines are checked more strictly. LocalSR only lists and starts engines from a verified install, and checks their files at each start. Engine Manager has a Verify button for a full check. An engine that fails is marked for reinstall, and LocalSR falls back to the built-in engine. Older or interrupted installs need one reinstall (#159).
  • Offline engine packages are now signed with their version, system and architecture, and LocalSR refuses older ones or ones for another system (#159).
  • Updated Rust and Python dependencies with security fixes.

Fixes

  • Edit on Windows. Every edit failed after 10 seconds. The check of the editing program got stuck because it inherited the connection between the app and its engine, which Windows blocks while the engine waits on it. Programs LocalSR starts, such as the editing program and an external FFmpeg, no longer inherit it (#160).
  • Engine exit. Fixed a deadlock that could freeze the app when the engine exited. This also affected 0.5.0.
  • Model folder moves. Safer handling of links, existing files and interrupted moves, including custom edit model paths.
  • Engine fallback. Failed engines fall back to the bundled engine without endless restarts. Interrupted imports can be recovered.

GPU engine downloads on Windows and Linux, and Mage-Flow on NVIDIA and AMD graphics, have not been tested on real hardware.

In v0.5.0-beta

What changed

  • Light theme and colour-blind friendly colours. Dark, Light or Match System, and an Okabe-Ito palette for every colour that carries meaning. Both are in the View menu and apply at once, also during a job (#129).
  • First-launch setup. New installs choose the appearance, automatic update checks, the anonymous count and crash reports on one screen. Nothing goes over the network before Continue. Existing installs keep their settings and never see it.
  • Update notice. When a newer version is out, a small notice offers Update, Skip This Version and What's New. Installing still waits until jobs have finished (#113).
  • Report a problem. In the Help menu and in Performance & Diagnostics. It opens a prefilled GitHub issue in the browser with redacted diagnostics that you see first; the app itself sends nothing.
  • Crash reports. If LocalSR or its engine quits unexpectedly, a short redacted report is kept on your computer, and at the next start LocalSR asks whether to open it as a GitHub issue. Nothing is sent automatically. Turn it off in the Help menu.
  • Video: Restore and Fix first. Videos can be restored at their own size and run the fixes before upscaling, like photos (#127). Upscale at 1× now runs no upscaling model: the size stays and only the fixes, video options and audio cleanup apply.
  • Video: audio cleanup. Removes background noise from speech, with DeepFilterNet3 or the stronger DPDFNet. The chosen model downloads the first time you use it (#137).
  • Low priority. Advanced → "Run at low priority" keeps other apps responsive. Jobs take longer, on a Mac about twice as long (#128).
  • Downloads. Up to three models download at once; the rest wait in a queue (#121).
  • File access. The app reads and writes only the files and folders you chose yourself (#117).
  • Smaller things. Confirm before deleting a recipe, saved recipes look like the Quick and Best cards (#124), an optional sound when a job finishes (#125), the interpolation unit is named (#118), a link to the custom-model tutorial, and a more visible delete border in Dark.
  • Dependency updates.

In v0.4.0-beta

What's new in 0.4

What changed

This is the first public release since v0.3.0-beta. It adds support for built-in graphics and Intel NPUs, updates inside the app on Windows and Linux, comparing saved results, HEIC and MOV output on the Mac, and a long pass over reliability and the interface. If you run the Windows or Linux build of v0.3.0-beta, install this version once from the download page; it uses the same settings, queue and models folder, and later versions update in the app.

Since v0.3.0-beta

  • Graphics and NPUs. On Windows, DirectML can use built-in graphics (Intel, AMD Radeon), and Intel graphics also appear as OpenVINO devices on Windows and Linux. A GPU is used only after LocalSR has compared its result with the CPU's, and a driver that crashes during that test is left alone. Intel NPUs run SPAN, Real-ESRGAN, FBCNN and NAFNet on Windows and Linux.
  • Updates on every system. Windows and Linux builds now update themselves, with signed update statements that also cover package sizes and parts. The update switches in the LocalSR menu stop the check at launch or the anonymous count.
  • Fixes before upscaling. Choose the model for each fix, run up to three in order (noise, JPEG, blur), and see in the Model plan how many models fit the task. A fix the model cannot process is skipped with a note instead of ending the job.
  • Compare. Pick up to four results in Outputs and compare them with a slider or linked boxes at full resolution. "Try others" queues two to four installed models on one image. Videos use the same slider and linked boxes with synchronised playback from one transport.
  • Output formats. On the Mac, HEIC images and MOV video with HEVC or Apple ProRes.
  • Video. Optional frame interpolation (2x, 4x, 60 or 120 fps), a Labs feature that is off by default.
  • Photos. Queued photos with the same plain recipe (SPAN, Real-ESRGAN or FBCNN, no fixes or Faces) run as a batch on Apple Silicon, about 1.9 to 2.8 times faster than one at a time on an M1 Pro. Grey scans keep their grey, and 16-bit grey and CMYK profiles are read correctly.
  • Models. Two DAT2 models join the library, the Hardware menu groups each graphics card's routes, and the model library shows each author, source and licence.
  • Packaging. Linux AppImages need glibc 2.35, so they run on Ubuntu 22.04, and the ROCm and CUDA ones are about a third smaller. On the Mac, Homebrew installs LocalSR and closing the window no longer quits the app.

Reliability

  • H.264 and HEVC export accepts low-sample-rate audio without "Cannot Encode Media".
  • With Video format Automatic, an early system HEVC encoder refusal can continue as AV1 with a note.
  • A result is never written over an existing file, including names that differ only in case or Unicode form.
  • Before a job starts, LocalSR checks that its files fit on the output's disk and keeps 8 GB free on the system volume. A full disk stops the queue once with a plain message.
  • The remaining-time estimate is rewritten. It starts only once a steady speed is measured, counts down by itself and changes in steps that do not flicker.
  • Core ML preparation has a 120 second limit per job. A program that does not finish is remembered and tried again after a week or after an app or macOS update. Intel NPU models are compiled in a separate process.
  • Engine processes are stopped as a whole group, and a damaged queue database is set aside so the app starts.
  • FFmpeg and the editing runtime are chosen only through the app's own file dialogs.
  • Editing on a Mac no longer stops for 2 GiB of swap.

Interface

  • Finished videos appear in Outputs with their duration and frame rate.
  • Browse other inputs and results while a video job runs.
  • Two start buttons: "Only this one" and "Upscale all N".
  • Inputs and Outputs tabs with counts; Compare opens only from "Compare these N".
  • A clearer running row, "Saving…" and "Stopping…" states, and removing inputs while a queue runs.
  • Click a result to show it, "Use as input" to use it as a new input, Clear on Outputs.
  • Help "?" tips on the Advanced controls and a hardware line on every library row.
  • The Illustration choice picks illustration models: Real-ESRGAN Anime 6B for Quick and RealPLKSR HFA2k for Best.

Download

Download page. Checksums are in SHA256SUMS and the .sha256 files.

Known limitations

  • The Windows and Linux builds of this version were tested by automated checks: the installed app starts and its engine answers. The hands-on testing was on an Apple Silicon Mac.
  • The Illustration choice was changed to the illustration models without a visual comparison against the previous behaviour.
  • The CUDA editions have never run on an NVIDIA GPU, and DirectML's NAFNet denoising misses its accuracy tolerance. Intel NPUs on Windows have not been tried on real hardware, and AMD NPUs are not supported.
  • Frame interpolation is a Labs feature; its 1080p and 4K speed and memory use on the Mac are not validated. De-flicker, editing, SeedVR2 and HDR preservation also remain experimental.
  • Windows installers are not code-signed, so SmartScreen asks first.

See KNOWN_LIMITATIONS.md for the current list. Report problems on GitHub Issues with your app version and steps to reproduce.

New in v0.3.0-beta

The Neural Engine on Apple Silicon. Quick photo (SPAN), Real-ESRGAN and JPEG cleanup (FBCNN) now run on the Neural Engine through Core ML, and Best photo (RealPLKSR) runs on the GPU through Core ML. On a MacBook Pro M1 Pro a tile became two to three times as fast (SPAN 19 against 38 ms, Real-ESRGAN anime 95 against 319 ms, FBCNN 61 against 149 ms) while using a fraction of the energy. Other models stay on the GPU.

Checked on your Mac. The first job with a model and tile size prepares it once, which takes up to a minute. LocalSR then runs the first tile both ways and keeps the Neural Engine only if it matches the usual result and is not slower; otherwise the job continues on the GPU. Newer Macs, whose GPUs can outrun the Neural Engine, decide for themselves.

Hardware: Neural Engine. The Neural Engine is its own entry under Advanced → Hardware and the default on Macs that have it; Apple GPU (Metal) keeps every model on the GPU. Before a job the status bar names where the selected model will run.

Videos about twice as fast. Quick runs each frame in one call instead of tiles, and decoding, upscaling and encoding overlap. A 15-second iPhone clip upscaled 4× went from 1.6 to 3.6 frames per second: about two minutes instead of five.

Automatic video format. The new default hands frames straight to the Mac’s hardware HEVC encoder while the next ones are upscaled. No Mac encodes AV1 in hardware, so MKV, HDR preservation, Windows and Linux use AV1, and every format can still be chosen directly.

Play before upscaling. A video plays in the preview before it has a result, with the same controls as a finished comparison, and the zoom controls beside the playback bar no longer disappear.

Installed Mac betas offer this version through the update check. Windows and Linux users download the new installer.

In v0.1.7-beta

Large results open in the comparison view. A 12 MP phone photo enlarged 4× becomes a 195 MP image. LocalSR could save it, but the preview decoder then rejected it as too large. Finished exports now use a separate decoder when needed, which sends a preview of at most 2048 pixels on the longest side to the app. The file you save keeps every pixel.

Less repeated work. The app reuses the latest result preview when it receives the same request twice. If you replace the file, it refreshes the preview.

The README also has clearer wording, a real before-and-after example and a new screenshot of the model library. Installed Mac betas offer this update the next time you open the app.

In v0.1.6-beta

More photo formats. HEIC and HEIF photos from iPhones and cameras, and JPEG XL, open on a Mac through macOS’s own decoders, upright and with their colour profile. AVIF, JPEG 2000 and GIF open too, and camera RAW files from Canon (CR2, CR3), Nikon, Sony, Fujifilm, Olympus, Panasonic, Pentax and others, not only DNG. LocalSR ships no new codec for any of them.

Edit works on 16 GB Macs. The memory check before an edit misread how much memory a Mac has free: it counted only part of it and kept 4 GB in reserve, so it refused FLUX.2 klein 4B on a 16 GB MacBook Pro that macOS itself reported as 70% free. It now asks macOS, keeps 2 GB in reserve, and watches the editor’s real memory use while it runs. On that Mac, with other apps open, an edit at 512 px takes about two minutes and does not swap. FLUX.2 klein 4B Q4_0 is the configuration tested so far; the larger bundles have not run on real hardware yet.

Progress you can see. An edit names what it is doing (reading the photo, reading your instruction, step 2 of 4, finishing the image) with a moving progress bar on the photo and in the status bar. The right model by default: a Mac starts with the best editing model that leaves most of its memory to macOS and your apps, FLUX.2 klein Q4_0 on 16 GB, Q8_0 on 24 to 32 GB and Qwen Image Edit from 36 GB; a model you chose is kept. Fixed: installing a newer disk image over a copy that had updated itself kept the older inference engine.

If you installed an earlier beta, the app offers this update the next time you open it. It replaces the inference engine as well, so the download is about 760 MB.

A proper install window. Opening the disk image now shows one window: LocalSR on the left, your Applications folder on the right and an arrow between them. Drag the icon along the arrow and LocalSR is installed. The mounted disk shows the LocalSR icon as well.

A centred icon. The terracotta pixel in the app icon and in the app’s own logo sat slightly right of and below the middle of its crop marks. It is now exactly centred.

In v0.1.4-beta

Edit with a prompt. Edit is a new task beside Upscale and Restore. Select a photo, write what should change (“make it winter”, “remove the sign”) and press Edit selected. The result is a new PNG in your output folder; the original stays untouched, and progress, cancel and the comparison work as for every other job. (Edit is experimental. Editing models in the library. A memory guard. Editing runs in its own process. LocalSR checks free memory before it starts, and a small supervisor stops the edit if the Mac runs short or starts to swap, instead of letting the system grind. Edits are 512, 768 or 1024 px on the longest side, one image at a time.

Video formats

LocalSR includes only royalty-free or patent-expired media formats, so the app itself never ships H.264, HEVC or AAC codecs. Photos are unaffected.

On macOS those formats go through the codecs that ship with the system, so most phone and camera videos open and export without anything else installed. H.264/HEVC exports written this way go into MP4; for MKV, and for formats macOS cannot read such as WMV, DivX or FLV, install FFmpeg (for example brew install ffmpeg). LocalSR uses an installed FFmpeg automatically, runs it as a separate program, and never downloads or bundles it. Converting through it uses extra disk space for a temporary lossless copy.

Updates

When you open LocalSR, it checks quietly for a newer beta. If one is available, a notice offers Update Now: the update downloads, is verified against LocalSR's signing key, then installs and restarts. While a queue is running, it waits until processing finishes. Settings, recipes and downloaded models are kept.

Earlier alpha builds cannot update themselves. Install the current beta once from the download page; later betas arrive in the app.

Choose the right installer

  • macOS 14+, Apple Silicon: v0.3.0-beta, a DMG that runs on the Neural Engine and the GPU (MPS) with CPU fallback, Developer ID signed and notarized by Apple. This is the most tested build, the only one with Edit, and it updates itself.
  • Windows 10 / 11, x86-64: v0.3.0-beta, an installer that runs on the CPU. It is not code-signed, so SmartScreen warns before it runs, and it does not update itself yet.
  • Linux, x86-64: v0.3.0-beta, an AppImage that runs on the CPU. Make it executable and run it; it does not update itself yet.
  • GPU editions: AMD ROCm for Linux, tested on a Radeon RX 9060 XT in earlier builds; NVIDIA CUDA for Windows and Linux, untested because it has not yet run on an NVIDIA card; and DirectML for Windows, untested, whose photo-denoising results can still differ from the CPU’s. The CUDA and ROCm editions are several gigabytes and come in parts. Details are in the project’s platform notes.

Still in development

Testing the GPU editions on real NVIDIA and more AMD hardware, and Labs features such as SeedVR2 video, de-flicker and HDR preservation are still in progress. Results are reconstructions: inspect text, faces and fine detail before relying on them. Report problems on GitHub Issues.

Models have their own terms

Not sure which model does what? The model guide explains every model, its best use, and its license in plain words · including what to check before downloading or using results commercially.

LocalSR's own code is MIT-licensed. Models download separately and keep their own licenses; each catalog entry shows its author, source and license before download.

Source and licenses

This software uses libraries from the FFmpeg project under the LGPLv2.1. LocalSR does not own FFmpeg. The corresponding source, build instructions and license notices for each build are published next to its installer on GitHub Releases, as a source and notices bundle for every edition, including the exact FFmpeg, OpenCV, LibRaw and GCC runtime sources. The editing runtime is stable-diffusion.cpp with GGML (MIT); its license notices are inside the app.

Verify your download

Compare the SHA-256 digest of your downloaded installer with the published checksum file.

On macOS:

shasum -a 256 LocalSR-v0.3.0-beta-macOS-arm64.dmg
