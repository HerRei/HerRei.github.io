LocalSR / Release notes

What's new in 0.4.

LocalSR 0.4.0-beta is out, the first public release since 0.3.0. It brings support for more hardware, updates on every system, comparison of saved results including videos, and a pass over reliability and the interface.

Compare your results

In Outputs, pick two to four saved results and choose Compare these N. A slider lets you drag between two versions of the same input; linked boxes show up to four, including results from different inputs. Zoom and pan stay linked, and LocalSR loads visible image detail from the saved file when you zoom in beyond the preview.

You can compare videos in the same slider or boxes. One transport plays, pauses and seeks all ready videos by time, and if one buffers, they wait and resume together. Audio comes from the first slot.

A calmer interface

The status bar has two start buttons: Only this one runs the selected picture and Upscale all N runs the queue. Inputs and Outputs have their own tabs and counts. Click a result to see it, choose Use as input to work on it again, or clear the Outputs list without deleting the files.

The running picture has its own progress line, with Saving and Stopping states when needed. Help tips explain Advanced controls, and every model library row shows which hardware the model can use.

More hardware

On Windows, DirectML can use built-in Intel and AMD Radeon graphics. Intel graphics also appear as OpenVINO devices on Windows and Linux, and Intel NPUs can run SPAN, Real-ESRGAN, FBCNN and NAFNet. Before trusting a GPU, LocalSR compares its result with the CPU's; a driver that crashes during the check is left alone.

Video

Frame interpolation is an optional Labs feature, off by default, that adds frames to motion. You can interpolate before or after upscaling, and the clip keeps its duration and compatible audio. On a Mac you can save HEIC images and MOV video with HEVC or Apple ProRes. Finished videos appear in Outputs with their duration and frame rate. With Video format Automatic, an early system HEVC encoder refusal can continue as AV1 with a note.

Safer by default

LocalSR never writes a result over an existing file, even when names differ only in case or Unicode form. Before a job it checks the output volume has enough space and keeps 8 GB free on the system volume. If a job cannot fit, LocalSR refuses it before starting.

The remaining-time estimate begins after a steady speed is measured and changes in steps that do not flicker. Core ML preparation has a time limit, and Intel NPU compilation runs separately so it cannot freeze the engine. FFmpeg and the editing runtime are run only if LocalSR found them itself or you chose them through the app's file dialogs.

Updates everywhere

Windows and Linux builds can now update in the app, as the Mac build does. If you use 0.3.0 on Windows or Linux, install this release once from the download page; later releases can update in the app. The installation uses the same settings, queue and models folder.

What to know before updating

The Windows and Linux builds were checked by automated tests that start the installed app and check its engine; hands-on testing was on an Apple Silicon Mac. Windows installers are not code-signed, so SmartScreen asks before they run. CUDA editions have never run on an NVIDIA GPU, DirectML's NAFNet denoising misses its accuracy tolerance, Intel NPUs on Windows have not been tried on real hardware, and AMD NPUs are not supported.

Frame interpolation is experimental, and its speed and memory use at 1080p and 4K on the Mac have not been validated. De-flicker, editing, SeedVR2 and HDR preservation also remain experimental. The Illustration choice now selects illustration models, but it has not been visually compared with the previous behaviour. Inspect restored detail and keep your originals.
